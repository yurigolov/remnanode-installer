# remnanode-installer

Два bash-скрипта для быстрого запуска ноды [Remnawave](https://docs.rw) на чистом VPS (Debian/Ubuntu):

- **`vps-check.sh`** проверяет, годится ли сервер под VPN: ресурсы, TUN/WireGuard, порты, доступность IP из России, репутацию IP, скорость. Ничего не устанавливает.
- **`setup-node.sh`** ставит ноду по схеме **VLESS Reality + self-steal**: Xray слушает 443, а всех, кто не является клиентом, отправляет на собственный сайт на nginx (`127.0.0.1:8443`) с настоящим сертификатом Let's Encrypt.

## Как это работает

```
клиент ──TLS, SNI=node1.example.com──▶ Xray :443 (remnanode)
                                         │
                свой клиент (ключ Reality подошёл)? ── да ──▶ VPN
                                         │
                                        нет
                                         ▼
                         nginx 127.0.0.1:8443 → обычный сайт с валидным сертификатом
```

Снаружи сервер выглядит как обычный сайт: браузер, сканер или проверка DPI получают настоящую страницу и сертификат именно на этот домен.

## Что нужно заранее

1. VPS на Debian 11+ или Ubuntu 20.04+, доступ по SSH под root или пользователем с sudo.
2. Домен (поддомен) с A-записью на IP сервера. В Cloudflare режим **DNS only (серое облако)**: с проксированием не выпустится сертификат, и Reality не будет работать как задумано.
3. Нода, созданная в панели Remnawave: из её `docker-compose.yml` понадобится `SECRET_KEY`.
4. Свободные порты 80 (выпуск сертификата) и 443 (Xray), плюс порт API ноды (по умолчанию 2222).

## Быстрый старт

Скопировать скрипты на сервер:

```bash
scp vps-check.sh setup-node.sh root@<IP>:/root/
```

Проверить сервер (около 1.5 минуты, с `--fast` около 30 секунд):

```bash
sudo bash /root/vps-check.sh
```

Установить ноду. Домен и `SECRET_KEY` скрипт спросит сам:

```bash
sudo bash /root/setup-node.sh
```

Или сразу параметрами:

```bash
sudo bash /root/setup-node.sh -d node1.example.com -k 'eyJub2Rl...'
```

## Параметры `setup-node.sh`

| Ключ | Переменная | Что это |
|---|---|---|
| `-d` | `DOMAIN` | домен ноды |
| `-k` | `SECRET_KEY` | ключ ноды из панели; можно вставить строку из compose целиком, вида `- SECRET_KEY="..."` |
| `-e` | `EMAIL` | почта для Let's Encrypt, необязательно |
| `-p` | `NODE_PORT` | порт API ноды, по умолчанию `2222` |
| `-y` | `ASSUME_YES=1` | ничего не спрашивать, на предупреждения отвечать «да» |

## Что делает `setup-node.sh`

1. Ставит nginx, certbot и утилиты. Если apt занят автообновлениями, ждёт до 10 минут.
2. Проверяет, что домен указывает на IP этого сервера.
3. Кладёт сайт-заглушку в `/var/www/<домен>` вместе со своей страницей 404.
4. Настраивает nginx на порту 80: проверка Let's Encrypt и редирект на https. Запросы по голому IP закрываются.
5. Выпускает сертификат; после каждого автопродления nginx перезагружается сам.
6. Поднимает сайт на `127.0.0.1:8443` с TLS 1.3 и HTTP/2.
7. Ставит Docker и запускает `remnawave/node` из `/opt/remnanode/docker-compose.yml`.
8. Если включён ufw, открывает 80 и 443.
9. Генерирует ключи Reality в `/opt/remnanode/reality-keys.txt` и печатает готовый inbound.

Повторный запуск безопасен: уже выпущенный сертификат, ключи и свой `index.html` скрипт не трогает.

## После установки: панель Remnawave

1. **Config Profile.** На каждую ноду отдельный профиль с inbound, который напечатал скрипт. В `serverNames` только домен этой ноды, `target` всегда `127.0.0.1:8443`. Профиль привязать к ноде.
2. **Hosts.** Адрес — домен ноды, порт 443, в поле SNI тот же домен.
3. Порт API ноды лучше открыть только для IP панели:

```bash
ufw allow from <IP_ПАНЕЛИ> to any port 2222 proto tcp
```

## Проверка

Кто слушает порты (80 и 127.0.0.1:8443 — nginx, 443 — Xray):

```bash
ss -ltnp | grep -E ':(80|443|8443)\b'
```

Сайт через Xray (должен ответить `HTTP/2 200` с сертификатом Let's Encrypt):

```bash
curl -vI https://node1.example.com/
```

Логи ноды:

```bash
docker logs -f remnanode
```

## Частые проблемы

| Что видно | Причина |
|---|---|
| `Could not get lock /var/lib/dpkg/lock-frontend` | на свежем сервере идут автообновления; подождать и запустить скрипт ещё раз |
| в браузере `ERR_CONNECTION_REFUSED` | Xray ещё не получил конфиг: профиль не привязан к ноде или нода не Online |
| `ERR_TOO_MANY_REDIRECTS` | в Cloudflare включено проксирование (оранжевое облако) с SSL «Flexible» |
| сертификат от Cloudflare или Google Trust Services | домен проксируется Cloudflare, нужно серое облако |

## Безопасность

- `SECRET_KEY`, `/opt/remnanode/docker-compose.yml` и `reality-keys.txt` содержат закрытые ключи. Не коммить их и никому не отправляй.
- Сайт-заглушка одинаковый на всех нодах, поставленных этим скриптом. Его текст публичен, поэтому лучше заменить его своим: положи свой `index.html` в `/var/www/<домен>/`, и скрипт его не тронет.
